# Как мы искали ботов

Задача: по событиям внутри суточного окна дать каждой `cookie_id` оценку от 0 до 1. Чем выше оценка, тем вероятнее автоматический сбор объявлений. Главная метрика: Precision при Recall не ниже 70%. События за концом окна в признаки не попадают.

## Результат

Итоговый ответ лежит в `output/submission.csv`. Это среднее рангов трёх CatBoost без User-Agent. В каждой модели теперь есть разброс координат курсора, число нулевых координат и самый частый город объявления. Остальные группы идут по нарастающей: базовые признаки, маршруты, контекст просмотров. На трёх временных проверках средний P@R70 равен **0,725** против **0,566** у прежнего ответа. Качество на скрытом test неизвестно.

Для выбора модели используем walk-forward кросс-валидацию: проверяем 11–13, 14–16 и 17–19 апреля, обучаясь каждый раз только на куках с уже закончившимся суточным окном. Результаты по отрезкам: **0,680 / 0,688 / 0,806**. Потом обучаем три модели на всём размеченном train и предсказываем test за 20–26 апреля. Каждая модель ранжирует куки внутри проверочного отрезка, а в итоговом файле внутри всего test. Потом усредняем три процентильных ранга. Итоговый `score` не является вероятностью и зависит от состава партии кук. Мы сравнивали много идей на этих трёх отрезках, поэтому оценка может быть оптимистичной; скрытый test покажет реальное качество.

Попробовали и четвёртый CatBoost поверх трёх первых, с подбором параметров через Optuna. На заранее отложенных 17–19 апреля он дал **0,778**, настроенные нижние модели со средним рангов **0,783**, прежнее среднее рангов **0,806**. Поэтому `output/submission.csv` пока остаётся прежним. Кандидат лежит в `output/stacked_submission.csv`; разбор есть в `notebooks/10_stacking_optuna.ipynb`. Число 0,806 относится только к этому блоку, а не ко всему скрытому тесту.

После разговора с автором другого решения проверили его идеи: ведущую категорию объявления, часы активности и скорость курсора. На одинаковых временных фолдах добавление категории во все три CatBoost дало **0,725** в среднем, практически столько же, сколько текущие **0,725**. На всех OOF-куках одной метрикой вышло **0,731 против 0,712**, зато на последних 17–19 апреля стало **0,742 вместо 0,806**. Время и кинематика тоже не дали устойчивого выигрыша. Основной ответ не меняли; опыт описан в `notebooks/11_peer_features.ipynb`.

Чужой результат 0,8431 нельзя сравнивать с нашими числами: Word2Vec обучали по сырым событиям, включая 40 779 строк за концом разрешённых окон, а один и тот же проверочный кусок использовали для early stopping, подбора Optuna и финального отчёта. Сами куки между train и validation не повторялись, но граница разрезала календарный день. Причину и размер завышения без повторного прогона отдельно не измеряли.

Отдельно проверили порядок действий через Word2Vec по соседним парам и тройкам событий. Ансамбль с векторами пар получил **0,737** в среднем по трём отрезкам против **0,725** у нынешнего ответа, но на последних днях упал с **0,806** до **0,767**. Тройки и обычные частоты переходов оказались слабее. Пока основной ответ прежний; кандидат лежит локально в `output/sequence_candidate.csv`, разбор в `notebooks/12_sequence_embeddings.ipynb`. Word2Vec на каждом фолде обучается только на прошлых куках и событиях внутри их окон.

## Как повторить

Нужен Python 3.12. Из корня проекта установи библиотеки и запусти скрипт:

```bash
python3 -m pip install -r requirements.txt
python3 run_solution.py
```

Скрипт заново читает `data/train.csv`, `data/test.csv` и `data/events.csv.gz`, строит признаки, проверяет модели по времени, затем обучает их на всём train. Он создаёт `output/final_validation_scores.csv` и `output/submission.csv`. Промежуточные таблицы из `output` для запуска не нужны.

Для отдельного опыта со стекингом запусти `python3 run_stacking.py`. Он использует сохранённые параметры из `stacking_params.json` и создаёт `output/stacked_submission.csv` и таблицу сравнения. Команда `python3 run_stacking.py --tune` заново перебирает варианты через Optuna, используя 16 попыток для каждого нижнего CatBoost и 24 для верхнего. Seed равен 42.

Чтобы пересчитать опыт с новыми признаками, запусти `python3 run_peer_features.py`. Его общая таблица лежит в `output/peer_feature_summary.csv`, а лучший новый кандидат сохраняется локально в `output/peer_best_candidate.csv`. Этот опыт не переписывает `output/submission.csv`.

Чтобы проверить пары, тройки и Word2Vec, запусти `python3 run_sequence_embeddings.py`. Сводка сохранится в `output/sequence_summary.csv`, подробные оценки и файл кандидата останутся локально в `output/`. Скрипт не меняет `output/submission.csv`.

## Что лежит в папках

- `notebooks/01_eda.ipynb`: данные, графики и продуктовый смысл задачи.
- `notebooks/02_baseline.ipynb`: первый простой ориентир.
- `notebooks/03_models.ipynb`: сравнение логистической регрессии, случайного леса и CatBoost.
- `notebooks/04_feature_engineering.ipynb`: ритм действий, маршруты и разнообразие.
- `notebooks/05_item_journeys.ipynb`: история объявлений, контекст и проверка отбора признаков.
- `notebooks/06_conclusion.ipynb`: сравнение ошибок и смешивание моделей до добавления курсора.
- `notebooks/07_pointer_location.ipynb`: проверка координат курсора и города объявления. Новый ансамбль получил 0,725 на временной валидации против 0,566 у прежнего ответа.
- `notebooks/08_single_full_model.ipynb`: проверка одной CatBoost с новыми признаками. Отобранный набор дал 0,716, все 108 признаков дали 0,696. Их ответы лежат отдельно в `output/single_context_submission.csv` и `output/single_full_submission.csv`.
- `notebooks/09_script_time_cv.ipynb`: разбор присланного скрипта, его разбиения внутри 16 апреля и проверка новых групп признаков по времени.
- `notebooks/10_stacking_optuna.ipynb`: подбор параметров трёх CatBoost и проверка четвёртого поверх них. Отложенный блок показал, что этот вариант уступает прежнему ответу.
- `notebooks/11_peer_features.ipynb`: проверка категории, времени и кинематики по группам и в ансамбле. Разбор результата другого агента и его Optuna.
- `notebooks/12_sequence_embeddings.ipynb`: сравнение частот переходов и Word2Vec по парам и тройкам событий на трёх временных отрезках.
- `notebooks/quickstart.ipynb`: пример из исходного набора данных.
- `utils/`: расчёт признаков и официальная метрика; `tests/`: проверки границ суточного окна.
- `data/`: исходные файлы; `output/`: предсказания и таблицы для сравнения.

Ноутбуки можно открыть из корня проекта или из `notebooks/`. В начале каждого рабочая папка переключается на корень, чтобы пути к данным и результатам оставались одинаковыми.

Использованы локально запускаемые библиотеки NumPy, pandas, scikit-learn, CatBoost, Optuna и Gensim. Их точные версии указаны в `requirements.txt`. Внешние API и большие языковые модели не использовались.
